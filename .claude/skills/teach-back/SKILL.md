# Skill: Teach-back

## Purpose
The project only counts if the owner can explain it in an interview. This skill
turns finished work into understanding.

## Process
1. **Break it.** Propose 1 to 3 experiments ("change X and see what happens",
   "remove this validation", "feed it dirty data"). The owner predicts the
   result first. Then run it and compare.
2. **Explain-back.** Ask the owner to explain the module in their own words,
   4 to 6 sentences, with one example from PetrIA. Check: the problem, the
   rule, who enforces it, the trade-off. Correct mistakes plainly.
3. **Learning notes.** Add to `petria/learning.md` in the private study-history repo: what we did, why, new
   concepts (with the JavaScript, Express, SQL Server or Spring equivalent) and
   interview questions with short answers.
4. **Algorithm spots.** If the batch had one, log it under "Algorithms used in
   production" with the interview question it answers. In the no-AI mode, the
   owner writes it and the agent only reviews.

## Rules
- Never skip the owner's prediction: it is the learning moment.
- Agents do not write the owner's no-AI algorithm spots.
- The English coaching stays with the lead, not with the role agents.
